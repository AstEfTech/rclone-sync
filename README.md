# rclone-sync: Google Drive / iCloud Drive → local disk

One-way sync from Google Drive or iCloud Drive to a local disk on a local server, every 15 minutes by default. Each provider is configured as a list of folder pairs (source → destination), each with its own sync type; schedule, pairs and user are set in the shared `config.yml`.
The default sync type is `copy`, which never deletes anything; `sync` and `move` are opt-in per pair (see [Folder pairs and sync types](#folder-pairs-and-sync-types)).

## Environment

| What | Value |
|---|---|
| Host | Local server (Linux); rclone, the script and systemd run as `run_user`, not root |
| Source | `providers.<name>.pairs.<pair>.src` (e.g. `gdrive:Media`; for Google: a regular account, OAuth client of type **Desktop app**, app status In production) |
| Destination | `providers.<name>.pairs.<pair>.dst` on a local disk (optionally a separate disk mounted at `mount_point`) |
| rclone config | `~/.config/rclone/rclone.conf` of `run_user` (`chmod 600`) |
| rclone install | via the script from rclone.org |

Getting the OAuth client ID and token and setting up the `gdrive` remote: [gdrive/CONNECTION_README.md](gdrive/CONNECTION_README.md). Do this before running `deploy.sh`.

## Layout

```
config.example.yml               # template of the shared settings (copy to config.yml)
deploy.sh                        # deploys one provider or all that have a block in config.yml
undeploy.sh                      # asks which provider to remove, removes its units and installed directory
common/                          # shared by all providers
├── config.sh                    # minimal config.yml reader (no yq needed)
├── pull.sh                      # main script, installed as <NAME>-pull.sh
├── watch-log.sh                 # tail -f of the latest log
├── pull.service.in              # unit template: oneshot, Nice=10, IOSchedulingClass=idle
└── pull.timer.in                # OnCalendar=@SCHEDULE@ (config.yml, default *:0/15), Persistent=true, RandomizedDelaySec=30
gdrive/
├── provider.conf                # provider differences: name, rclone options, minimum rclone version
└── CONNECTION_README.md         # getting Google credentials and configuring rclone
```

Layout on the server (`app_dir` from `config.yml`; each provider gets its own `$APP_DIR/<NAME>-pull/`):

| File | Path |
|---|---|
| Script | `$APP_DIR/gdrive-pull/gdrive-pull.sh` |
| Provider options | `$APP_DIR/gdrive-pull/provider.conf` |
| Logs | `$APP_DIR/gdrive-pull/log/YYYY-MM-DD_HH-MM-SS.log` (one per run, deleted after `keep_log_days`, default 14) |
| Lock | `$APP_DIR/gdrive-pull/.lock` |
| Settings | `$APP_DIR/gdrive-pull/.env` (generated by `deploy.sh` from `config.yml`: `MOUNT_POINT`, the `PAIR_NAMES/SRC/DST/MODE` arrays, optionally `MIN_FREE_GB`, `KEEP_LOG_DAYS`; chmod 600) |
| Units | `/etc/systemd/system/gdrive-pull.{service,timer}` |

## Installation

```bash
git clone https://github.com/AstEfTech/rclone-sync.git
cd rclone-sync
cp config.example.yml config.yml
$EDITOR config.yml  # common block and the block of the provider you install
./deploy.sh gdrive    # as run_user, not via sudo
```

One `config.yml` in the repository root serves all providers: the `common` block (`run_user`, `app_dir` and the optional `mount_point`) holds the defaults, and `providers.<name>.pairs` holds the folder pairs of each provider (if `mount_point` is set, every `dst` must be inside it). Any `common` key can be overridden in a provider block (for example another `run_user` or `mount_point` for one provider). Each provider is deployed from `common` and its own block only, so you can leave the settings of providers you do not use as they are. Two pairs (of one provider or of different ones) cannot share a `dst` (or nest one inside the other): `deploy.sh` refuses.

After editing `config.yml`, run `./deploy.sh` in the repository root: it redeploys every provider that has a block under `providers` (skips the others, reports failures at the end). `./deploy.sh <provider>` deploys just one; without arguments on a terminal it offers a list.

`config.yml` is required: `deploy.sh` will not run without it. It holds no secrets (credentials stay in the `rclone.conf` of `run_user`). The file is read by a small built-in parser, so no `yq` is needed; the supported subset is nested mappings indented with 2 spaces and `key: value` scalars (quotes and `# comments` are fine; lists and multi-line values are not). The script checks that rclone is installed (if not, it asks for confirmation and installs it via the script from rclone.org) and that the remote of every pair's `src` is configured for `run_user`; then it copies the files to `$APP_DIR/<NAME>-pull/`, generates the provider's `.env` there, substitutes values into the unit template, runs `daemon-reload` and restarts the timer. `config.yml` is not tracked by git. Redeploying is safe: it takes the same lock as the sync, so it refuses to run while a sync is in progress.

Line endings: during installation `deploy.sh` strips CR from `config.yml`, `provider.conf`, scripts and units, so CRLF from Windows is not a problem. The exception is the root `deploy.sh` and `undeploy.sh`: bash will not run a file with CRLF. If they arrived with CRLF, run `sed -i 's/\r$//' *.sh common/*.sh` once in the repository root.

## Folder pairs and sync types

Each provider syncs any number of folder pairs. A pair is a named block under `providers.<name>.pairs` with a source (`src`, `<remote>:<path>`), a destination (`dst`, a local directory) and an optional `mode`:

```yaml
providers:
  gdrive:
    pairs:
      media:
        src: gdrive:Media
        dst: /mnt/storage/gdrive/media
        # no mode: copy
      documents:
        src: gdrive:Documents
        dst: /mnt/storage/gdrive/documents
        mode: sync
```

| `mode` | rclone command | Effect |
|---|---|---|
| `copy` (default) | `rclone copy` | New and changed files are copied; nothing is ever deleted |
| `sync` | `rclone sync` | `dst` becomes an exact mirror of `src`: files missing in `src` are **deleted** from `dst` |
| `move` | `rclone move` | Files are copied, then **deleted from `src`** (the source gets emptied) |

`mode` is resolved per pair: the pair's own value, else the provider block, else `common`, else `copy`. Pairs of one provider run one after another within a single timer run and share its schedule, lock and log. Pair names may use letters, digits, `-` and `_`. Use `sync` and `move` only when you are sure: they delete data (`rclone sync --dry-run` is a good first check by hand).

## Removal

```bash
./undeploy.sh            # as run_user: pick the provider from the list, then confirm
./undeploy.sh gdrive -y  # provider named explicitly; -y skips the confirmation
```

Stops and removes `<NAME>-pull.timer` / `.service` and deletes `$APP_DIR/<NAME>-pull/` (script, settings, logs). Files already copied to the destinations, the rclone remote and `config.yml` are kept. If a sync is running, it is stopped; a run started by hand blocks the removal until it finishes.

## Script logic

1. `flock -n` on `.lock`: if the previous run is still going, exit with code 0.
2. If `mount_point` is set, check `mountpoint $MOUNT_POINT`; for each pair check at least `min_free_gb` GB of free space (default 5) (on the mount, or on the destination's filesystem when `mount_point` is not set).
3. For each pair in turn (a failed pair does not stop the others; the exit code is that of the last failure): the free-space check, then `rclone <mode> <src> <dst>` (pairs and modes come from the provider's generated `.env`) with the provider's options from `provider.conf` (`RCLONE_ARGS`; for Google Drive:
   `--transfers 4 --checkers 8 --drive-skip-gdocs --exclude ".Trash-*/**"`) plus `--stats 30s --stats-file-name-length 0`,
   the log is written via `--log-file` into `log/`.
4. `LOG_LEVEL=INFO` by default, overridable via an environment variable (`LOG_LEVEL=DEBUG` for debugging).
5. A non-zero rclone exit code is logged and returned to the caller (the unit is marked as failed).

## Operation

```bash
# enable the timer
sudo systemctl enable --now gdrive-pull.timer

# manual run (does not block the terminal)
sudo systemctl start --no-block gdrive-pull.service

# status and journal
systemctl list-timers | grep gdrive
journalctl -u gdrive-pull -f

# latest run log
tail -f "$(ls -t $APP_DIR/gdrive-pull/log/*.log | head -1)"   # or $APP_DIR/gdrive-pull/watch-log.sh

# after editing unit files (better to edit the template and rerun deploy.sh)
sudo systemctl daemon-reload
```

## Behavior

- **Overlapping runs.** systemd does not start a second instance of a oneshot unit, and `flock` guards against manual runs. Missed triggers do not pile up.
- **Interruption.** An interrupted file is downloaded again (rclone writes to a temporary `.partial`); completed files are skipped.

## Solved problems

| Symptom | Cause / solution |
|---|---|
| `redirect_uri_mismatch` | The OAuth client must be of type Desktop app |
| Cannot publish to Production | Fill in Branding: name, email, homepage, privacy policy |
| `permission denied` on `mkdir` | every `dst` must be owned by `run_user`; for NTFS/exFAT set `uid`/`gid` in fstab |
| `permission denied` on `/tmp/gdrive-pull.lock` | The lock was moved to the script directory; always run as `run_user`, not via `sudo` |
| `systemctl start` blocks the terminal (oneshot) | Use `--no-block` or rely on the timer |

## iCloud Drive

The same scheme for iCloud Drive lives in `icloud/` and works independently of `gdrive/` (its own `providers.icloud` block in the shared `config.yml`, units `icloud-pull.{service,timer}`, installed into `$APP_DIR/icloud-pull/`). Credentials and the remote setup: [icloud/CONNECTION_README.md](icloud/CONNECTION_README.md). Do this before running `deploy.sh`.

Differences from Google Drive:

| | Google Drive | iCloud Drive |
|---|---|---|
| rclone backend | `drive` (stable) | `iclouddrive` (experimental, rclone 1.69+) |
| Authentication | own OAuth client + token from a computer with a browser | Apple ID + regular password + 2FA code, entered on the server itself |
| Token lifetime | does not expire (app In production) | trust token is valid for **30 days**, then `rclone config reconnect icloud:` |
| `src` of a pair in `config.yml` | `gdrive:Media` | `icloud:SomeDir` |
| rclone options | `--transfers 4 --checkers 8 --drive-skip-gdocs` | `--transfers 2 --checkers 4` (the iCloud API is stricter about request rates) |
| Photos | – | a separate remote with `service=photos`, read-only |

```
icloud/
├── provider.conf                # NAME=icloud, --transfers 2 --checkers 4, rclone >= 1.69
└── CONNECTION_README.md         # logging in to iCloud and configuring rclone
```

Everything else (script, units, `deploy.sh` logic, `watch-log.sh`, `config.yml` handling) is shared in `common/` and the root `config.yml`; the provider only supplies `provider.conf`. A new provider is a new folder with `provider.conf` (the root `deploy.sh` and `undeploy.sh` find providers by it), plus its block under `providers` in `config.example.yml`. Installation, operation and script logic are the same as above, with `icloud` instead of `gdrive` in all names:

```bash
cd rclone-sync                                # the shared config.yml is already filled in
./deploy.sh icloud                            # as run_user, not via sudo
journalctl -u icloud-pull -f
sudo systemctl start --no-block icloud-pull.service
```

| Symptom | Cause / solution |
|---|---|
| Authentication errors about a month after setup | The 30-day trust token expired: `rclone config reconnect icloud:` |
| Login fails with a correct password | An app-specific password was used; only the regular Apple ID password works |
| `Missing PCS cookies from the request` | With Advanced Data Protection enable "Access iCloud Data on the Web" on the iPhone and approve the prompt on the trusted device |
| `unknown backend type "iclouddrive"` | rclone is older than 1.69; update it via the script from rclone.org |

## Possible improvements

- Failure notifications.
- `--fast-list` for large trees.
